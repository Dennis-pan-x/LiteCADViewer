# LiteCAD Viewer 0.1.0 validation

Validation date: 2026-10-19. Windows x64, Rust 1.99.1, NVIDIA GeForce RTX 5060 / DirectX 12. This record concerns the executable built from the independent LiteCAD workspace, not a renamed copy of an older CADCraft executable.

- Cargo metadata resolves ten local workspace members, all inside this repository: the frontend and nine required CADCraft-derived core crates. The resolved dependency graph contains no `cadcraft-engine`, `cadcraft-constraints`, `cadcraft-ui-egui` or `cadcraft-mcp` package.
- Formatting, workspace clippy with warnings denied, and all workspace tests passed using a single build job.
- A release build from this workspace reports `LiteCAD Viewer 0.1.0`. Executable SHA-256: `6f83b3100f2ebd1abf5387b3e2ddad670eecf7b696efce641616fef80a893278`.
- Newly generated DXF, DWG and 10,000-circle DXF inputs were opened through the actual executable. PNG/PDF output was created, PDFs reopened and Chinese/Φ/±/° text checked. Source hashes stayed unchanged. A malformed DWG returned an error without changing the input.
- Fresh CPU/GPU captures checked drawing silhouettes, transparency, wipeout and XLINE/RAY ordering. GPU drawing used one mesh for thirty settled navigation updates, with zero CPU raster requests. The 10,000-circle sample measured about 16.7 ms GPU versus 33.5 ms CPU median settled-view latency on this machine. This includes scheduling/presentation, is not a GPU timestamp, and is not a general performance guarantee. GPU startup overhead remains.
- A separate native DWG capture with the renamed application and selected icon was inspected; it is the screenshot in the README.

DWG fixtures were generated by CADCraft itself. This is a same-core round trip, not proof of independent DWG fidelity. SHX/big fonts, proxy/custom objects, complex layouts and 3D still require independent checks. Native runtime validation and published binaries currently cover Windows x64 only.

Developer checks:

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo build --locked --release -p litecad-viewer
```

Runtime diagnostics use fresh output paths and refuse overwrites:

```sh
litecad-viewer --version
litecad-viewer --probe drawing.dwg new-probe-directory
litecad-viewer --capture new-native.png --lang zh-CN drawing.dwg
litecad-viewer --capture new-gpu.png --benchmark drawing.dxf
litecad-viewer --capture new-cpu.png --benchmark --cpu drawing.dxf
```
