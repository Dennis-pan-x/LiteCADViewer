# LiteCADViewer 0.1.2 validation

Validation date: 2026-10-19. Windows x64, Rust 1.99.1, NVIDIA GeForce RTX 5060 / DirectX 12. This record concerns the executable built from the independent LiteCAD workspace, not a renamed copy of an older CADCraft executable.

- Cargo metadata resolves ten local workspace members, all inside this repository: the frontend and nine required CADCraft-derived core crates. The resolved dependency graph contains no `cadcraft-engine`, `cadcraft-constraints`, `cadcraft-ui-egui` or `cadcraft-mcp` package.
- Formatting, workspace clippy with warnings denied, and all 685 workspace tests passed using a single build job.
- A release build from this workspace reports `LiteCADViewer 0.1.2`. Executable SHA-256: `d8d964e6945dd4b6e141b92164c5b80767d34aa11c74ebabcc613b5a59b0eaf8`.
- Newly generated DXF, DWG and 10,000-circle DXF inputs were opened through the actual executable. PNG/PDF output was created, PDFs reopened and Chinese/桅/卤/掳 text checked. Source hashes stayed unchanged. A malformed DWG returned an error without changing the input.
- Rendering baseline from 0.1.0: fresh CPU/GPU captures checked drawing silhouettes, transparency, wipeout and XLINE/RAY ordering. GPU drawing used one mesh for thirty settled navigation updates, with zero CPU raster requests. The 10,000-circle sample measured about 16.7 ms GPU versus 33.5 ms CPU median settled-view latency on this machine. This includes scheduling/presentation, is not a GPU timestamp, and is not a general performance guarantee. GPU startup overhead remains.
- A fresh native 0.1.2 DWG capture was visually inspected with the peregrine-falcon toolbar icon and English interface. The actual backend was GPU (RTX 5060 / DirectX 12), one geometry mesh and zero CPU raster requests. This capture is the README screenshot. All nine Windows PE icon payloads match the new ICO and differ from the CADCraft editor. Legacy locale-argument acceptance was checked in 0.1.1; it was not rerun for this artwork-only update.

DWG fixtures were generated by CADCraft itself. This is a same-core round trip, not proof of independent DWG fidelity. SHX/big fonts, proxy/custom objects, complex layouts and 3D still require independent checks. Native runtime validation and published binaries currently cover Windows x64 only.

Developer checks:

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo build --locked --release -p litecad-viewer
```

```sh
litecad-viewer --version
litecad-viewer --probe drawing.dwg new-probe-directory
litecad-viewer --capture new-native.png --lang en drawing.dwg
litecad-viewer --capture new-gpu.png --benchmark drawing.dxf
litecad-viewer --capture new-cpu.png --benchmark --cpu drawing.dxf
```
